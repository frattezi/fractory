# An approved Quick Ticket brief passes the Spec Gate

A small, settled change agreed in a conversation can skip grilling and the Spec: the `quick-ticket` skill writes a short brief (change, why, acceptance criteria, out of scope), the owner approves it in the conversation, and `to-tickets` creates the Ticket from it as it would from a Spec. That approval is the Spec Gate for that brief; the Ticket Gate and the PR Gate still apply as the repo's Mode says. Changes that need more than a couple of Tickets, leave a design question open, or touch a contract, ADR or glossary term go through `grill-with-docs` and a Spec. We chose this because a full Spec for a one-Run change only adds latency, while ADR 0003 still holds: a human approves the intent before any Run starts. The CLI refuses to create a Ready Ticket while the repo's Ticket Gate is on, so the short path cannot skip that Gate.
